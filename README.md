# canton-zk-evm

Ostia, a Canton zkEVM (chain id 770101), is an EVM chain whose blocks are ordered by Canton and proven by a zero-knowledge virtual machine, so that an EVM block and the Canton actions it needs settle together in one Canton transaction.

Every EVM block becomes one Canton transaction, and only once it is proven. That transaction carries the block, its proof and the Canton actions the block asked for. Canton's confirmers check the proof. Daml checks that the block follows the chain's current head. The block and its actions commit together, or neither does.

What a block asks of Canton is written down on the EVM by one contract, the gateway, which is part of the chain from its first block. Each request is called a leg, and there are three kinds:

- a deposit: a Canton token is locked with the gateway, and its wrapped form is minted on the EVM;
- a withdrawal: the wrapped form is burnt, and the gateway releases the Canton token to a Canton party;
- a payment: an ERC-20 payment made through the gateway executes a Canton allocation that the payer and the payee agreed to for that payment and no other.

From Daml package 0.5.0 (29 October 2026) two more legs carry an ERC-20 to Canton and back as a twin. A lock pays the ERC-20 into a vault, an EVM contract with no owner and no key, and Daml mints the same amount of a CIP-0056 token, the twin, to a Canton party. A release pays the ERC-20 out of the vault against a redeem request that the holder of the twin signed, and Daml burns the twin. Both are payments of the gateway, so the proof covers them as it covers any payment.

The proof fixes the gateway's state, so it fixes the legs. `Advance` settles exactly the legs the proven block recorded, or the whole transaction fails and the block does not commit. A block cannot land without its legs, and a leg cannot settle without its block. Before it proves a block, the builder reads the block's legs, and if one cannot settle (an allocation is gone, or a receiver has not agreed to receive), it leaves out the transaction that asked for it. If the allocation is taken back after that check, Canton refuses the submission, nothing moves, and reth goes back to the last committed block. On DevNet the builder runs all the time (`builder.py run`) and cuts a block whenever transactions wait, and makes an empty block when a minute passes with none; `builder.py once` makes a single block, as the local network and the demo do. By default it makes one block at a time; DevNet ran it with `--max-in-flight 3` on two GPU provers until 28 October 2026 and runs it with `--max-in-flight 2` on one GPU prover since (see Status), and it still submits the blocks to Canton in order. It fills a block by the gas its transactions use, and normally offers reth no more than a cap on their raw bytes. There are no throughput targets yet. See [docs/DESIGN.md](docs/DESIGN.md) for the design and [docs/METRICS.md](docs/METRICS.md) for measurements, hardware and versions.

## Status

Ostia opened on Canton Network DevNet on 22 October 2026. The chain id is 770101, the RPC is `https://ostia.devnet.romeprotocol.xyz/rpc`, the explorer is `https://ostia.devnet.romeprotocol.xyz` and the faucet is `https://ostia.devnet.romeprotocol.xyz/faucet`. [docs/TRY-OSTIA.md](docs/TRY-OSTIA.md) has connection and deployment examples and a section on [the Canton twins and Canton Coin](docs/TRY-OSTIA.md#canton-twins-and-canton-coin-on-devnet), and the docs site has the rest: <https://docs.rome.builders/canton-zk-evm/canton-zk-evm>. To run Ostia yourself, this repository starts a local Canton network that keeps no state between runs unless you ask it to.

Since 25 October 2026 the builder fills a block by the gas its transactions use instead of the gas they declare, and limits the raw transaction bytes it offers for a block (an oversized first transaction is still offered, so it does not wait for ever). On 25 October the gas cap was 30,000,000 and the byte limit 196,608, one block was in flight, and plain transfers ran at 64 a second in steady state; the 30,000,000 gas cap binds at 1,428 per block. Since 27 October 2026 DevNet's gas cap is 60,000,000 (`SetGasCap` at 07:20 UTC, the new limit reached at 09:06 UTC) and the byte limit is 393,216.

DevNet's builder has run with `--max-in-flight 3` since 22:37 UTC on 26 October (the most blocks in flight is one more than the number of provers) on two spot GPU provers, one proof on each GPU, until 19:27 UTC on 28 October, when the second prover machine was stopped; since then it runs `--max-in-flight 2` on one GPU prover. Since 04:26 UTC on 27 October it also runs a pre-check on every block (ziskemu, a predicted proof time budget of 120 s) before the block is proven. The code default is still 1. ## Layout

| Folder | What it holds |
|---|---|
| `network/` | The reth launch (peer discovery always off), the genesis, the local Canton network, the scripts that start it all and the smoke test |
| `tests/` | Tests that run in CI |
| `docs/` | The design ([DESIGN.md](docs/DESIGN.md)), how to connect to DevNet and use the twins ([TRY-OSTIA.md](docs/TRY-OSTIA.md)), and what was measured on which machine ([METRICS.md](docs/METRICS.md)) |
| `verifier/` | Checks the wrapped proof in plain Rust |
| `mpt/` | Checks a value in the proven EVM state |
| `guest/` | The EVM program that gets proven, with this chain's rules built in |
| `prover/` | Scripts to run the prover, and the first proof |
| `gateway/` | The gateway contract that records each block's legs, the vault that holds the ERC-20s behind the Canton twins, and their tests |
| `sidecar/` | The service beside each Canton confirmer |
| `daml/` | The chain record (from 0.5.0 with its registry of EVM contracts), the block record, and the Daml side of deposits, withdrawals, payments and the locks and releases of twins |
| `builder/` | Makes a block, gets it proven, submits it to Canton |
| `explorer/` | A block explorer for Ostia, with a tROME faucet and an in-browser proof check (see [explorer/README.md](explorer/README.md)) |
| `load/` | The mixed load kit (tokens, NFTs, ERC-3643, Uniswap V2, a RedStone price consumer, TACEO's Merces contracts with client-side proofs only) and what one DevNet run measured |
| `apps/otc/` | An OTC app in its own Daml package: a seller's offer of a Canton token for an ERC-20 payment, and the trade a venue makes of it (see [apps/otc/README.md](apps/otc/README.md)) |
| `apps/twin/` | The Canton twin of an ERC-20 held in an Ostia vault, in its own Daml package: a CIP-0056 token (V1) with transfer and allocation factories and the admin's mint and burn (see [apps/twin/README.md](apps/twin/README.md)), and the twin registry service that serves the token standard's registry API for the twins and the parts of lock ids (see [apps/twin/registry/README.md](apps/twin/registry/README.md)) |
| `demo/` | A deposit, a payment, a withdrawal, a payment whose allocation is taken back, and a tampered proof (run on a GPU on 2026-10-05; `results/` holds the runs and the smoke test), and `twin.py` and `cc.py`, which show each step of the Canton twins and of Canton Coin on DevNet |

`PINS` lists the exact versions and image digests everything is built against.

## Running the tests

You need Docker, `bash`, `curl`, `jq`, `openssl` and Python 3. The Canton integration tests require Linux x86-64 and Java 21. The demo rehearsal also needs Python 3.12 or newer and Rust. The Rust tests use the toolchain in `rust-toolchain.toml`. Explorer tests need Node 22.18 or newer. `PINS` separates the prover's Node 20.20.2 (`NODE_VERSION`, for snarkjs) from the explorer's Node 24 image (`EXPLORER_NODE_IMAGE`).

```sh
tests/static.sh                  # pins and genesis agree
tests/refuses_missing_flag.sh    # the reth launch refuses a missing or wrong discovery flag, or a forbidden option
tests/udp_control.sh             # the UDP check fails on a container with a UDP listener (no reth)
tests/discovery.sh               # starts the pinned reth, checks it has no peers, stops it
tests/fixtures.sh                # the recorded proof is consistent (needs no GPU)
tests/network_static.sh          # reth only through launch.sh, the Canton config, the recorded smoke result
tests/network_checks.sh          # the compiler pin check, the DAR's id, the stop on another programVK (no GPU)
tests/canton_network.sh          # the pinned Canton, the real Daml package and one Advance (Linux x86-64, Java 21, Python 3; no GPU)
gateway/build.sh --check         # the checked-in gateway and vault code is what Gateway.sol and Vault.sol compile to (Docker)
gateway/tests/run.sh             # the gateway on a real reth, started with peer discovery off (Docker, curl, jq, Python 3 with the packages in demo/requirements.txt)
tests/guest-repro.sh             # the guest build runs in one fixed folder, so the source folder does not change the ELF (stand-ins for the ZisK tools; the same check on real ZisK passed on 2026-10-04, see guest/README.md)
tests/demo_static.sh             # the demo's pins, tamper switch and genesis override, and its recorded results (no GPU)
tests/demo_rehearsal.sh          # the demo and explorer with a stand-in proof (Linux x86-64, Docker, Java 21, Rust, Python 3.12+; no GPU)
tests/network_pipeline.sh        # the builder with two blocks in flight (and, with PIPELINE_DEPTH=3, three with two stand-in provers) on the local network: a flood, a refusal, a lost reply, and at depth 3 a kill -9 and a three-block move back (nightly in CI, pipeline-nightly.yml; same needs as the rehearsal)
tests/demo_explorer_static.sh    # the explorer's images are pinned, and what its container is given (no Docker)
(cd explorer && npm ci && npm test)  # the explorer's tests, against fakes (Node 22.18+; CI uses EXPLORER_NODE_IMAGE in PINS)
(cd guest/rules && cargo test)   # the chain rules and their hash (needs Rust)
```

Settings such as ports and the state folder come from environment variables; see the top of `network/reth/launch.sh`. The Engine JWT secret is generated per run into `state/`, which git ignores.
